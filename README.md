# 短信清理 · Android

当前目标公开版本：**v0.1.1 / versionCode 6**。公开版本从 v0.1.0 重新起始，代码包含此前迭代的改进；Android versionCode 继续递增。详见 [CHANGELOG.md](CHANGELOG.md) 与 [SECURITY.md](SECURITY.md)。

为 OPPO Reno10 Pro 5G 的批量短信整理需求制作的**临时清理工具**。中文界面，本地处理，无联网权限、广告或分析 SDK。Android 11+。

## 功能

- 正文关键词 + 发件号码/标识组合查询，支持发件人精确或包含匹配，按字面匹配，`%` 和 `_` 不视为通配符。
- 轻点短信卡片选择，点击“查看全文”或长按查看全文，并快捷精确筛选同发件人。不查联系人姓名。
- 全选当前查询的全部结果、逐条选择/取消、确认后批量删除。
- 查询改变后清空选择，删除按短信 ID 执行，不整段删除会话。
- 所选短信导出 JSON，使用系统文件选择器，不需要全部文件访问权限。
- JSON 仅用于保存/查看，本版本**不提供恢复导入**。

## 重要安全限制（安装前必读）

Android 只允许默认短信应用写入/删除系统 SMS。只读查询无需默认角色，但需要用户授予读取短信权限。ColorOS 可能另有短信/后台权限限制，**尚未在 OPPO 真机验证**。

这不是完整的默认短信客户端：**不支持 MMS 下载、RCS、发送短信及通话快捷回复**。成为默认期间，这些功能可能失效，MMS 甚至可能丢失。不要长期设为默认，不要用于紧急通信。本应用会尝试保存默认期间收到的普通 SMS 到系统收件箱，但不能保证成功，尚未经双卡真机验证。

推荐安全流程：
1. 先在原应用备份重要短信，记住原默认短信应用名称。
2. 本应用授予读取权限，查询、选择、导出 JSON。建议把备份保存在本机，不要上传私密短信。
3. **先开启飞行模式**，然后点击删除按钮，阅读风险并通过系统弹窗临时指定默认。应用不会替你更改系统设置。
4. 角色切换后重新查询/选择；再次点击删除，核对数量并确认。删除是永久操作，无法撤销。
5. **立即恢复原默认短信应用**（底部提供设置入口），确认恢复后再关闭飞行模式。

飞行模式检查只能降低风险，不保证系统无法通过 Wi-Fi calling 收到消息，也不能阻止用户在后台关掉飞行模式。若不能接受任何收信影响，勿授予默认角色，只使用查询/导出功能。

短信权限属于受限制权限；部分设备或安装器可能需要额外允许，若普通安装无法授权，请不要通过来路不明的提权工具绕过。先检查系统“应用权限/默认短信应用”。

## 构建

依赖 JDK 17、Gradle 8.10.2、Android SDK platform 35 + build-tools 35.0.0。

```sh
bash scripts/test-filters.sh
gradle lintDebug assembleDebug assembleRelease
```

此仓库使用系统 Gradle，未内置 wrapper。CI 固定 Gradle 版本并安装 SDK。

## GitHub 自动构建与正式签名发布

普通 main/tag 推送、PR 和默认手动运行只执行测试、lint 和 debug 构建，不读取正式签名凭据。测试 APK 在 `debug-test-only-not-for-upgrades` Artifact 中，**不是稳定升级包，不附加到 GitHub Release**。

发布 GitHub Release 或在 main 上手动运行并勾选 `signed_release`，才会启动独立正式签名任务。它用下面配置的**同一把长期密钥**签名、使用 `apksigner verify` 校验、比对预先固定的签名证书 SHA-256、检查应用 ID/版本与 tag，最后生成：

- `sms-manager-v0.1.1.apk`（文件名跟随版本号）：经过签名核验的可安装包。
- `SHA256SUMS.txt`：APK 文件的 SHA-256。
- `release-metadata.json`：版本、源提交、APK SHA-256 与签名证书 SHA-256。

Release 发布后只附加上述正式产物，**不再上传未签名 release 或 debug APK**。缺配置或校验失败会让正式发布任务明确失败，且不上传新的安装包；测试构建仍可正常通过。以前发布的未签名/debug 附件不会被工作流自动删除，请不要继续用那些附件安装。

### 需要仓库所有者先配置

本次代码变更**没有生成、上传、保存或配置任何密钥/密码**。需要你决定使用哪个长期 Android 签名密钥，并通过 GitHub 仓库 Settings → Secrets and variables → Actions 配置：

| 类型 | 名称 | 内容 |
| --- | --- | --- |
| Secret | `ANDROID_KEYSTORE_BASE64` | 包含稳定签名私钥的 keystore 的 Base64 编码（编码不是加密） |
| Secret | `ANDROID_KEYSTORE_PASSWORD` | keystore 密码 |
| Secret | `ANDROID_KEY_ALIAS` | keystore 内签名密钥的 alias |
| Secret | `ANDROID_KEY_PASSWORD` | 该密钥密码；若与 store 密码相同仍需填入 |
| Variable | `ANDROID_SIGNING_CERT_SHA256` | 对应签名证书的 SHA-256 指纹，64 个十六进制字符，可含冒号；**不是 APK 文件哈希** |

请不要把凭据发到聊天、README、Issue 或提交进 Git。保留安全的离线密钥备份；遗失私钥就无法正常更新同签名应用。证书指纹可用本机 `keytool -list -v -keystore <keystore> -alias <alias>` 查看，密码由命令交互输入，不放在命令行或记录中。若没有已有密钥，需先自行创建并妥善保管，或另行明确授权协助处理；此工作流不会替你生成。

密钥只在签名步骤的 runner 临时目录解码，限制文件访问并在退出时清理，不纳入 checkout、缓存或 artifact。密码通过 apksigner 的环境变量入口传递。对固定证书进行比对可以防止误配成另一把密钥，但不替代仓库与 Actions 的权限保护。仅在可信、审核过的提交运行正式签名；建议限制能修改工作流、推送 main 和发布 Release 的人。不要在不可信分支运行带凭据的手动签名。

### 版本与发布步骤

1. 在 `app/build.gradle` 更新 `versionName`，并让 `versionCode` **严格大于所有已分发正式包**。当前为 `0.1.1` / `6`。以后每次版本升级都要递增，工作流不代替你追踪历史已分发包。
2. 将已审核代码提交到 main，发布同名 tag `v0.1.1` 的 GitHub Release。tag 与 APK versionName 不符会拒绝发布。
3. 检查 `signed-release` 和 `publish` 都成功，再下载正式 APK。只有 debug 检查成功不代表已经完成签名。
4. 后续使用同一应用 ID、同一签名密钥、递增 versionCode 发布，才能正常覆盖升级。工作流不会切换或轮换密钥。

### 从旧 debug/其他签名包迁移

Android 不允许用不同签名证书直接覆盖同一应用 ID。仅重命名 APK、换 versionCode 或反复安装不能解决；不要绕过系统校验。

- 若仍拥有旧安装包对应的签名私钥，可评估继续使用该密钥。但临时 CI debug 密钥通常未保留，不应假定能找回。
- 若签名不一致且无法取得原密钥，通常需要先卸载旧应用，再安装正式包。**先恢复系统原默认短信应用，再核对备份，最后才卸载。**
- 卸载会清除本应用的筛选状态、操作日志、权限和内部数据。当前应用没有完整内部数据恢复功能；需要的日志/设置请先记录。通过系统文件选择器导出的 JSON 请确认位于独立文件夹且可读取；JSON 不是一键恢复备份。
- 系统短信由 Android/ColorOS 的系统短信数据库管理，通常不会随本清理工具卸载而删除；**未验证你的具体设备和卸载选项，不能作绝对保证**。重要短信请先通过原短信应用或可信系统备份方案备份，并验证备份可用，再考虑卸载。不要在未核实备份时贸然清除数据。
- 安装正式包后重新授予权限，并先用少量不重要短信验证。没有在 OPPO 真机验证过此迁移过程。

这是侧载原型，不代表符合 Google Play 短信权限上架政策。

## 安全补强（仍不能保证收信安全）

- 申请默认角色前保存原默认应用包名。独立状态栏持续显示当前角色，打开系统设置后会核对是否真正恢复原应用；仅打开设置**不等于**已恢复。此应用不能静默替用户切换默认角色。
- 默认期间尝试显示持续恢复提醒；系统重启、角色变化和重新打开应用会重新检查。提醒受通知权限、系统限制、强制停止等影响，不保证一直可见。关闭应用不会解除默认角色。
- 普通 SMS 保存改为异步，并校验系统返回的保存 URI；失败时留下本地错误记录，不再无条件宣称保存成功。没有实现失败短信的内容重放/恢复，必须向发送者核实。
- MMS 通知只记录异常，**不保存内容、不下载、不补收**。飞行模式仍只是减风险手段，不覆盖 Wi-Fi calling，也不是收信安全保证。
- 删除任务独立于 Activity，操作前及每条删除前重新检查默认角色和飞行模式；逐项写入操作日志。屏幕旋转后可查看任务摘要；若进程中断，展示已确认数量及可能未确认的一条，不会自动重试。不可撤销删除无法实现跨系统短信库/应用日志的原子事务，未确认时需重新查询。
- 接收失败记录仅保存错误说明，不保存短信正文或号码。JSON 备份仍含私密内容且不是可一键恢复的备份格式。

新增纯 Java 中断日志摘要测试，覆盖运行中、进程中断、部分确认、未确认单条、正常完成与主动停止。


## v0.2.0：删除结果核验与界面改版

### 修复的确定问题

旧版把系统 `delete()` 返回 0 当作正常结束，且不查询短信是否还在库中。这会掩盖未生效删除。新版本逐条查询前后状态；返回 0 且原 ID 仍存在时，仅用 `_id = ?` 集合 URI 路径再尝试同一条，不扩大到会话或全表。仍存在、异常或删除后无法核验，立即停止后续删除并给出结果。

结果区分：已核验不在库、操作前已不存在、失败、未确认和未处理。结果显示在持久卡片和自动弹窗；支持查看详情及停止后续删除（不能撤销已经删除的短信）。操作进程中断也会展示已落盘结果，不自动重试。

这修复了代码中“失败无明显反馈”的问题，**不是已查明 OPPO 设备上拒绝删除的具体原因，也不等于已经通过 Reno10 Pro 真机验证**。如果仍失败，请记录结果弹窗中的系统返回和异常类型，再检查 ColorOS 的短信权限/默认短信应用限制；不要把完整私人短信发到 issue。

### 新界面和交互

- 浅色卡片、圆角筛选面板、分层排版、固定底部批量操作及选中数量。
- 独立权限空态、加载进度、无结果提示；不再反复自动弹读取权限。
- 发件人支持精确匹配开关，短信卡片轻点选择、长按详情。
- 从默认角色申请或飞行模式设置返回，保留仍存在的选择；授权后明确提示“尚未删除”，必须再次确认。
- 屏幕重建保留筛选和所选 ID；普通刷新只移除已经不在结果中的 ID。
- 默认角色风险栏和安全与设置入口常驻，收信/MMS 限制不变。

### 验证范围

纯 Java 协议测试覆盖正常删除、返回 0 且仍存在、同 ID 兼容重试、删除前/后查询异常、权限变化、未执行时已不存在等 13 个场景（67 个断言），并保留 6 个过滤测试、11 个日志摘要断言。Android 35 SDK 编译检查与 GitHub CI 不替代真机权限、视觉及接收测试。


## v0.2.1：默认角色核验与自定义图标

- 补齐 Android 11+ 查询默认短信应用所需的 `SMS_DELIVER` package visibility 声明，不申请 `QUERY_ALL_PACKAGES`。
- 使用 `RoleManager.isRoleHeld(ROLE_SMS)` 核对自身角色，结合可读取的默认包名；角色和包名矛盾时不执行删除。只有包名不可读但 RoleManager 明确持有时，使用系统角色结果，而非把空包名误判为未授权。
- 记录系统申请返回的 `RESULT_OK` / `RESULT_CANCELED`，返回前台后进行最多约 3 秒的有限只读复查；系统回调成功本身不会触发或授权删除。核验成功后仍需用户再次确认删除。
- 未核实或矛盾时显示可复制诊断（Android 版本、角色状态、默认包名、回调结果，不含短信内容），提供系统默认应用设置入口。不给 root/ADB 强行改角色，也不绕过 ColorOS 安全限制。
- 自定义短信主题图标：蓝底白色短信气泡、青绿色整理完成标记；支持自适应图标、Android 13 单色主题图标与独立通知图标。

缺少 visibility 声明及立即依赖单一查询结果是确认的代码问题，但**不能据此确定 OPPO 用户本机角色申请失败的唯一原因**。仍需更新后核对实际系统诊断。此前收信/MMS 限制不变。

官方依据：[Telephony.Sms.getDefaultSmsPackage](https://developer.android.com/reference/android/provider/Telephony.Sms#getDefaultSmsPackage(android.content.Context))、[RoleManager](https://developer.android.com/reference/android/app/role/RoleManager)。


### 公开仓库的发布边界

- 公共 PR/fork 只执行不含正式签名 Secrets 的测试任务。没有 `pull_request_target` 特权执行路径。
- 签名任务限制为 `chadlwm/sms-manager` 本仓库，手动触发只允许 main；Release 对应提交必须已进入 main 历史，才能进入含凭据步骤。
- 签名不使用 Gradle 缓存，测试作业只读取缓存；checkout 不持久保存 Git 凭据；第三方 Actions 固定为官方仓库标签核对的提交 SHA。
- 这些控制不替代维护者权限和 main 代码审查。仓库所有者应自行评估分支保护、签名 Environment 人工批准和 Actions 设置；本次仅修改仓库代码，不自动配置安全权限。
- 公开之前仍须审查整个 Git 历史与旧 Release 附件；扫描当前目录不能证明历史没有敏感内容。
